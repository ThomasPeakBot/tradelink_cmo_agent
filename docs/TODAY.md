# Today: a focused TradeLink workday

Open **Today** from the sidebar. Choose four, four-and-a-half or five hours and generate a plan. Twenty minutes for evidence review and twenty for the end-of-day check-in are reserved; the three proposed tasks must fit within the remaining time. Generation is manual, not part of the 4am data sync. Sync fresh provider data first when necessary.

With OpenAI configured, the planner requests structured output grounded in company knowledge, subscriber pace, billing, organic channels, experiments, reviewed approvals, memory, selected Drive excerpts and recent daily outcomes. Reference IDs must exist in stored evidence, and server validation rejects over-budget or malformed plans. Tasks include a deliverable, success criterion, rationale and source labels/Drive links. Model output can still be mistaken: review it before approving. Demo context is visibly labeled and stale or missing evidence should be flagged. Local mode uses clearly labeled prioritization rules; an OpenAI failure does not silently become a successful local generation.

A plan is stored once per Eastern calendar date in PostgreSQL. Generating again does not overwrite existing work. Edit unfinished tasks instead; edits return them to Proposed. Approve an internal task, defer it, or complete an approved task with an observed outcome and optional actual minutes. Completion is a user report, not independent proof of success. Completed outcomes remain recorded and become institutional-memory observations. Planned time is bounded; actual time can exceed estimates and is recorded honestly. Deferred work is not automatically executed or copied; recent outcomes/blockers are available to the next generated plan.

Save the end-of-day check-in to record outcomes, learnings and blockers. Revisions update one stable memory entry rather than create duplicates. The current plan and up to three recent daily summaries feed CMO context. The UI retains the last seven stored workdays for reference. Optimistic version checks reject edits based on a stale browser tab; refresh before retrying.

Approving a Today task only accepts an internal work item. It does not approve or execute external publishing, spending, email, DMs or campaign changes. Use the separate approval workflow for external actions, then execute manually. No external executor or tools are registered.

All mutations require an authenticated administrator and trusted origin. Task ownership within the selected plan and work budgets are validated transactionally. Shared company plans use an advisory lock/version guard for updates. Generation requests have a durable one-minute cooldown and a unique date constraint; failed generation retains existing plans. Audit events record creation and updates without exposing API credentials.

## Step-by-step guides and AI prompts

New plans include a persisted JSON guide per task: required inputs, 3–6 numbered steps whose estimates fit the task budget, 1–2 self-contained copy-ready AI prompts, a definition-of-done checklist and an explicit human approval boundary. Prompts identify a suitable manual tool (ChatGPT/Codex, CMO chat, Higgsfield or browser assistant), include task-specific context and list any private files/data the user must supply. Copying a prompt does not send it to another app or execute it. Users must paste/run it themselves and review the result.

Existing unfinished tasks have a Generate AI instructions button. The ADMIN-only same-origin Today route uses a durable one-minute per-task lease, generates outside the transaction and rechecks plan version before saving. Guides do not change task approval or recorded outcomes. Editing task title/deliverable/success criterion/time clears its old guide, preventing stale instructions. Existing plans/history remain valid with nullable guides. `scripts/populate-today-guides.ts --apply --migrate` fills missing guides on today's unfinished tasks without replacing priorities, statuses or outcomes.

Local evidence mode supplies clearly provisional task-specific templates with the same structured steps/prompts; live AI guide failures preserve the existing task rather than silently substituting a generic guide. Stored source content remains untrusted data. Prompt fields and lists are bounded in both the OpenAI schema and server validation. Neither guides nor copied prompts add external-action capabilities. Publishing, outreach, spending and campaign changes still require separate explicit human approval and manual execution.

Deferring a task requires a reason. The task and reason remain visible, and a source-linked owner-report memory records the deferral and its alternative. One new proposed task is added with steps and AI prompts, avoiding existing task titles and fitting the remaining budget after the 40-minute reserve (including recorded overruns). Existing and completed tasks are preserved. The live model considers the reason and stored company evidence; if unavailable, a clearly labeled local evidence proposal is offered for review. No replacement is automatically approved or executed. Concurrent changes abort the operation, and repeated replacement requests are rate limited. If under 15 minutes remain, adjust the plan first.

Each task has **Discuss with CMO**, a persistent per-user conversation grounded in that task's deliverable, instructions, status, workday, the latest 16 messages from its thread, and stored company evidence. The UI shows the latest 30 thread messages; older messages remain in PostgreSQL. Task conversations are separate from general CMO Intelligence chat and other tasks. Archived/reset task conversations remain stored by task ID. Clarification alone does not edit, approve, defer or execute a task. Use the explicit **Save a confirmed clarification to CMO memory** form to record a reviewed learning for future planning. Local evidence mode shows the task context and explains that free-form conversation requires the configured OpenAI provider; it does not pretend to reason conversationally.
